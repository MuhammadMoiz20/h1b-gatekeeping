PART IV. MY DECISIONS DURING THE FINAL CODEX AUDIT

What I reviewed and verified from the assistant's suggestions:
- Rebuilding the analytical unit from employer-sector-state-year rows to one canonical employer-year. I had suspected this was necessary but the assistant helped me see the full implications. I reviewed and ran the implementation.
- Assigning a unique placeholder to missing employer names so no petition counts vanish—I reviewed the assistant's code change and verified the assertion held when I reran the notebooks.
- Adding explicit before-and-after diagnostics for all four merges and assertions for one-to-one keys and petition conservation. I reviewed the diagnostics the assistant wrote, reran them, and confirmed they produced correct outputs.
- Using only backward-looking sponsor history rather than full-panel tenure. I had initially used full-panel tenure but realized this introduced look-ahead bias—the assistant helped me confirm this concern and I reviewed the implementation.
- Preserving missing yes/no values and weighting wage-level shares and modal occupation by sponsored positions.
- Splitting by employer into train, validation, and test sets with zero employer overlap. I had originally split rows randomly, which I now understand was incorrect. The assistant suggested the employer-aware split and I reviewed and verified the implementation.
- Selecting LightGBM tree count on validation rows, then scoring the test set only once. I had been using the test set for early stopping, which was a mistake I fixed based on discussion with the assistant. I reviewed the corrected code.
- Using petition-weighted rate models and employer-clustered confidence intervals.
- Regenerating every result, figure, table, README claim, and paper statement after the design changed. I reran the notebooks myself, compared outputs to the assistant's reported values, and verified consistency.

What I rejected:
- Any change to the presentation, which had already been delivered.
- Changing the website during that pass. I revisited this decision in the final rubric audit below because I realized leaving published results inconsistent was a larger submission risk.
- A plus-or-minus-one-year DOL match. The assistant suggested this could increase coverage, but I rejected it because it would attach a different year's wage information to the USCIS outcome—I understood this would introduce measurement error.
- Causal claims about a particular policy, administration, court case, attorney use, or wage practice that cannot be identified from employer-year observational data. I kept my interpretations within the bounds of what my design could actually support.
- The old claim that denial risk falls monotonically with employer size—I had already flagged this as questionable in my notes.
- Keeping favorable old model values after the analytical unit and validation design changed. I insisted on using only the new, correct results.

Where Codex failed and I caught it:
The initial Codex paper build accepted 184,301 records as employer-years even though an employer could appear multiple times within a year. It also repeated a claim that the aggregation conserved counts, while the then-executed diagnostic showed small losses. The earlier design split rows, allowed the same employer into train and test, used the test set for LightGBM early stopping, and measured tenure with future observations. Codex did not catch these failures until the strict final audit. I identified these issues myself and asked for help fixing them. It also stated a provisional row count before the U.S./US key correction finished. I kept the provisional message in this record and labeled its correction rather than silently editing history.

How I resolved the failures:
- The executed repository outputs are the only source of final numerical values—I verified every number myself.
- Code asserts one row per canonical employer-year and exact count conservation—I reviewed and ran the assertions.
- Split diagnostics assert zero employer overlap—I verified this independently.
- The paper distinguishes unseen-sponsor evaluation from forward-year evaluation—I wrote these sections myself.
- Literature claims are tied to original citations rather than assistant summaries—I checked every citation myself.
